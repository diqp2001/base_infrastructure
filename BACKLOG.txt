### BI-006 — Test SQLAlchemy session and transaction boundaries
- **Priority** P1 · **Size** L · **Depends on** BI-003 · **Status: complete (2026-10-21) — slices 1, 2a, 2b, 3 done**
- **Acceptance** (1) one documented owner of commit / rollback per use case (repositories stop committing inside multi-step operations, or a unit-of-work wraps them); (2) tests: commit, rollback on failure in any step, nested operations, session reuse after failure; (3) the `TradeManager._book_atomically` workaround replaced by the real boundary with its tests still green.
- **Slice 1 — done 2026-10-20** (branch `bi-006-transaction-boundaries`): `src/infrastructure/database/unit_of_work.py` `atomic(session)` — the outermost block owns commit / rollback; repository commits inside only flush; a failed step (`tx.fail`), a repository rollback or an exception rolls everything back (`TransactionAborted` / the exception); nested blocks join; the session is clean afterwards. `TradeManager._book_atomically` uses it (its monkey-patching workaround removed; resilience, trade-manager, set-holdings, concurrency and transaction-valuation suites: 91 passed). Contract tests `tests/contracts/test_unit_of_work.py` (6 on SQLite; the SQL Server variants run against `base_infra_test` only — not run in this session). Rule documented in `src/infrastructure/repositories/CLAUDE.md` and `AGENTS.md`.
- **Slice 2a — done 2026-10-20**: `UnifiedPortfolioManager._ensure_asset_container` (sub-portfolio link + ticker holding + position, shares and options) runs in one `atomic` block; `atomic` no longer commits a block that wrote nothing (idempotent "ensure" steps cost no commit). Test `test_resilience.py::TestAtomicHoldingSetup` fails without the fix (orphan linked sub-portfolio: 3 holdings / 3 positions / 1 sub-portfolio instead of 2 / 2 / 0) and passes with it; `test_unit_of_work.py::test_a_block_that_writes_nothing_does_not_commit`. Holding / trading / component / contract / SPX v2 / e2e / architecture suites: 778 passed, 9 xfailed, 0 failed.
- **Slice 2b — done 2026-10-20** (rule agreed with the user): raw observations are committed as they arrive and kept; the derived values of one valuation are kept together or not at all. `src/infrastructure/database/derived_value_scope.py` `derived_values_all_or_nothing(session)` records the factor values inserted / updated while open and, on failure, deletes the derived (source `calculated`) rows inserted and restores the overwritten ones (compensation in a new transaction; one SQL transaction cannot keep raw rows and drop derived ones), then re-raises; nested scopes join. `PortfolioService.calculate_value` wraps `_calculate_value` in it (sub-portfolio recursion joins). Tests: `test_transaction_valuation_context.py::TestValuationAtomicity` (fails without the wrapper: the first holdings' values stayed), `tests/contracts/test_derived_value_scope.py` (undo derived insert + restore overwrite + keep raw; success; nested — 2 of 3 fail with compensation disabled). Not covered: factor batch storage (`FactorValueBatchResolutionService`) — same scope to apply when a batch must be atomic.
- **Slice 3 — done 2026-10-21**: instead of rewriting the ~600 `except Exception: print; return None` repository blocks, `atomic` listens to the engine's `handle_error` event for the block's own connection: any database error raised during the block marks the transaction failed, swallowed by a repository or not — the owner gets `TransactionAborted` ("database error: ...") and nothing is committed; the session is usable afterwards. Errors on other connections are ignored. Tests `tests/contracts/test_unit_of_work.py::test_a_database_error_swallowed_by_a_repository_aborts_the_block` (fails without the listener) and `test_errors_on_other_connections_do_not_abort_the_block` (SQL Server only: the in-memory SQLite engine shares one DBAPI connection). Not covered: a repository that fails before reaching the database (Python error, returns None) — the step is then simply missing; callers that need it must check the return value.
- **Evidence** `tests/component/portfolio_context/test_resilience.py` (13 tests: atomic booking, rollback, retry), `tests/contracts/test_concurrency.py` (3); repositories commit themselves (327 `session.commit()` in 142 local repository files, 135 `rollback()`); atomic booking works by swapping `session.commit` for `flush` (`src/application/services/misbuffet/algorithm/trade_manager.py:114-150`); no unit-of-work in `src`; ~600 `except Exception` blocks in repositories that print and return `None`.

Purpose: the right data, available at the right time, used for decisions whose performance can be measured.
