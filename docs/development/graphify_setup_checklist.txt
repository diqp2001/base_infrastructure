               (writes .claude/skills/graphify/SKILL.md + references/), `--platform <name>` for others (codex ...).
               Always-on configs (`graphify claude install` etc.) and `graphify hook install` (git hooks rebuilding
               on commit / checkout) are separate, optional.
             - Build: `/graphify .` in the agent, or headless `graphify extract`; `--code-only` indexes code only
               (tree-sitter AST + call graph, offline, no API key); `--update` incremental; `--no-viz`.
               `GRAPHIFY_BACKEND=none` disables every LLM backend.
             - Output: graphify-out/graph.json, GRAPH_REPORT.md, graph.html.
             - Query: graphify query "<q>", graphify path A B, graphify explain "<name>" (exit 0 / 3 ambiguous /
               4 no node). Queries logged locally to ~/.cache/graphify-queries.log (GRAPHIFY_QUERY_LOG_DISABLE=1).
             - Ignore: honours .gitignore, --exclude patterns, project .graphifyignore.
             - Data leaving the machine: code never (local tree-sitter). Docs / PDFs / images are sent to an LLM
               (the agent's model, or a configured provider in headless mode) unless code-only / backend none.
               README states no telemetry.
             - Documentation gaps: the README does not state the exact files `graphify install --project` writes
               for Claude Code (beyond the skill folder), whether nested .gitignore files are honoured, or the
               .graphifyignore syntax -> verify by inspection in P.02 / P.03 before committing anything.
