SUMMARY

Last updated     : 2026-11-05
Goal             : screen equity ETFs with listed options and < 50 constituents for a potential long-dispersion /
                   short-index-volatility trade: SHORT 1 ATM call on the ETF, LONG ATM calls on every constituent,
                   sized by the ETF weights and scaled to be dollar-delta neutral; keep a candidate only when the ETF
                   call bid >= the constituent calls' ask cost (executable prices). A potential dispersion trade, NOT
                   an arbitrage (implied-vol differences, correlation, dividends, borrow, early exercise, settlement
                   and bid/ask all sit between the payoff inequality and market prices).

5. Conflicts with the current architecture
   - "Do not create a standalone script": a project manager is the repo's unit of a project, but here it only
     orchestrates; all logic goes to domain / application services so P.09 and a future trading project reuse it.
   - The ETF entity needs a schema change on base_infra (owner approval + COPY_ONLY backup, rule of this repo).
   - CompanyShareOption's name implies a company underlying; reusing it for ETF options is a naming compromise
     (D3) — creating ETFOption would duplicate it.
   - CompanyShareOptionImpliedCorrFactor is equal-weight; section 19 needs weights — extend it (optional weights
     argument), do not add a second correlation factor.
   - Greek factors compute BSM locally, while the screen must use IBKR's quoted greeks (section 7: "actual option
     delta"). Both are kept: the quote's model delta is primary, the factor's BSM delta (from the same quote's IV)
     is a cross-check, and a large difference is a data-quality flag.
   - Market-data lines: one ETF with 49 constituents needs ~100 quotes (50 options + 50 underlyings); the
     streaming service caps at 95 lines and the trader shares the paper login -> the screen uses snapshots in
     batches on its own client id (D6), with IBKR pacing.
   - A project folder must not import another project's code (SPX v2 pricing model): shared math goes to the
     domain.

6. Assumptions about option data to verify (in P.03, read-only, live login)
   - The options bundle the owner subscribed (2026-11-02) serves OPRA quotes for ETF and single-stock options on
     the API (not only TWS), real-time, and the paper login shares it.
   - tickOptionComputation arrives on a SNAPSHOT request (model greeks need a few seconds; some contracts only
     return bid/ask greeks).
   - reqSecDefOptParams lists expiries and strikes per exchange / trading class; adjusted (non-standard
     multiplier) classes after corporate actions appear as separate trading classes and must be excluded or
     handled through the multiplier.
   - Contract multipliers: 100 for US equity / ETF options, but deliverable-adjusted series exist -> read the
     multiplier from the contract details, never assume 100 (section 11).
   - US ETF and equity options are American, physically settled; early exercise (dividends) is ignored by the
     European payoff simulation and must be named in the results.
   - Option volume / open interest via generic ticks 100 / 101 are previous-day values for OI.
   - Holdings weights: issuer files give market-value weights; N-PORT gives values to normalise; cash, futures
     and swaps lines must be removed before normalising (synthetic / derivative ETFs then fail the "equities
     only" test).
   - Weights are value weights: the raw position per constituent is proportional to
     w_i x ETF_price / (S_i x multiplier_i) contracts per ETF-equivalent share, not to w_i alone; the
     delta-neutral scaling is applied on top (sections 6, 7, 11).
   - DELTA_TOLERANCE = 0.01 is read as |net dollar delta| / ETF call dollar delta <= 1 % (the spec gives no
     unit).
   - Test 2 (perfectly correlated stocks -> basket ~ ETF call) holds when K_i = S_i x K_ETF / ETF_price, i.e.
     every strike at the same moneyness; listed strike grids make it only approximate in practice.

     the archive covers 6 months. A missing close makes an observation incomplete (excluded, never zero).
